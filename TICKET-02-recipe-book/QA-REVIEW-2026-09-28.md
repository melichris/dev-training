### 🔴 F-08: A dated, historical QA review document was edited after publication

**Where:** [QA-REVIEW-2026-09-14.md](QA-REVIEW-2026-09-14.md), edited by commit `66892c3`
(2026-09-24), part of a find-and-replace of `"vue-tsc --noEmit"` → `" vue-tsc --build"`
(note the stray leading space) applied across multiple files including this one.

**Why this matters more than a code bug:** A QA review dated 2026-09-14 is a record of what
was observed on 2026-09-14. If new information changes the picture, the correct move is to
**add a note or a follow-up review** — exactly what this document (`QA-REVIEW-2026-09-28.md`)
is doing. Editing the original file to read differently erases the evidence trail a reviewer
relies on, and it produced self-contradictory text in the TICKET-03 copy of the same edit
("`vue-tsc --build` without `--build` does not follow references" — see TICKET-03's review).

**This is not accused as intentional deception** — it reads like an automated find-and-replace
run across the whole repository without checking which files should never be touched. But the
effect is the same as altering a record, and it must not happen again.

**Required fix:**
1. Restore `QA-REVIEW-2026-09-14.md` to its original text (git history has it — see the
   commit immediately before `66892c3`).
2. If the command reference needs updating for accuracy, add a dated addendum instead:
   *"Update 2026-09-24: the type-check command has since been changed to X."*
3. Going forward: **never edit a file whose name contains a past date.** These are append-only.
