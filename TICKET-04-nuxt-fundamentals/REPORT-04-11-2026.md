## 1. Findings Addressed

### F-03: Make list loading states reachable

Added `lazy: true` to the post and product list fetches. Both list pages now
render explicit pending and error states. The post and product detail pages
also retain lazy fetching and pending/error branches.

### F-14 and F-17: Correct product API behavior and remove duplicated data

- Added `server/utils/products.ts` as the shared product fixture.
- Updated both product API handlers to use the shared fixture.
- The product detail API returns HTTP 400 for invalid IDs and HTTP 404 for a
  valid ID with no matching product.

### F-15: Correct current route documentation

Updated `TICKET.md`, `APPROACH.md`, and the application README to use the actual
post API paths (`/api/post` and `/api/post/:id`) and identify the real route
files. The application README now documents both the post and product API
routes and their shared data utilities.

The existing `REPORT.md` still contains outdated plural post-route references.
It was intentionally left unchanged to preserve the past report. This report
records the correction and current verified behavior.

### F-16: Return HTTP 404 for missing detail pages

The post and product detail pages now promote server-side fetch errors to
Nuxt page errors, preserving the API status. Missing records therefore return
HTTP 404 at both API and page level. Detail URLs use reactive route parameters.

### F-06: Correct product list markup

The products page now renders one `<ul>` containing the product `<li>` items,
rather than a separate nested list for each product. It also has explicit
loading, error, and empty-list states.
