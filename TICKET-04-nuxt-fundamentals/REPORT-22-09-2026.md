## Summary

The project was narrowed to the post flow only, as requested. The package-manager conflict was resolved and the app is aligned to npm. The remaining post-related issues were then fixed and verified: API validation, explicit error handling, shared post data, and TypeScript type-check support.

Product routes are intentionally out of scope for this report and were not changed as part of this post-only remediation effort.

---

## Fixes already applied

### 1) Package manager normalized to npm

The project now uses npm as the canonical package manager.

**Evidence:**

- [nuxt-fundamentals/package-lock.json](./nuxt-fundamentals/package-lock.json) is present.
- The pnpm lockfile and workspace config were removed.
- [nuxt-fundamentals/README.md](./nuxt-fundamentals/README.md) now states the package manager explicitly.

This resolves the lockfile drift and removes the conflict between npm and pnpm.

### 2) Post API now returns proper HTTP errors

The handler in [nuxt-fundamentals/server/api/post/[id].ts](./nuxt-fundamentals/server/api/post/[id].ts) now validates the incoming id and throws `createError` for invalid or missing posts.

**Current behavior:**

- invalid id => `400`
- missing post => `404`
- valid post => `200`

### 3) Post detail page now handles fetch errors explicitly

The page in [nuxt-fundamentals/app/pages/posts/[id].vue](./nuxt-fundamentals/app/pages/posts/[id].vue) now reads the fetch `error` state and shows a proper failure message while still preserving the loading and not-found states.

### 4) Type-checking is configured

The project in [nuxt-fundamentals/package.json](./nuxt-fundamentals/package.json) now includes:

- `typescript`
- `vue-tsc`
- `typecheck` script

**Verification:**
`npm run typecheck` passes successfully.

### 5) Shared post data has been centralized

The duplicated mock data was moved into [nuxt-fundamentals/server/utils/posts.ts](./nuxt-fundamentals/server/utils/posts.ts), and both the list and detail server routes now consume that shared source.
