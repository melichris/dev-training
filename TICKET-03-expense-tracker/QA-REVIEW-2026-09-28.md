### 🔴 F-11: `provide`/`inject` defect is unfixed, and the report repeats a claim already proven false

**Where:** `useExpenses.ts:47` still contains `provide('currencySymbol', '$')`, inside the
data composable, not in `ExpenseTracker.vue` as the 2026-09-14 review required.

**Where the claim lives:** `REPORT.md:88` still states: *"`currencySymbol` provided in
`ExpenseTracker.vue`, injected in `ExpenseRow.vue`."* This exact sentence was already
identified as false in the 2026-09-14 review (§6.2 of the overall review). It has not been
corrected in two weeks.

**What did improve:** `TotalsDisplay.vue:19` now injects `currencySymbol` instead of
hardcoding `$` — real progress on the symptom, none on the root cause or the report.

**Rule reminder:** When a report claim is flagged as false, the fix is not complete until
*both* the code and the sentence describing it are corrected. A report that still asserts
something already disproven is worse than no report, because it signals the flag wasn't read.

### 🟠 F-11a: `REPORT.md`'s validation write-up describes the old, wrong logic

**Where:** `REPORT.md:34` ("Technical Decisions") still describes
`isNaN(parsedAmount) || parsedAmount <= 0` — the logic that let `Infinity` through. The actual
code (`ExpenseForm.vue:56-60`) now correctly uses `!Number.isFinite(parsedAmount) || parsedAmount <= 0`,
which is the right fix. The report text was never updated to match. No edge-case input table
(`12abc`, `Infinity`, `0`, `-5`, `1e3`) was added, as required by the 2026-09-14 review.
